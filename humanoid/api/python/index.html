    RobotModel ¶

    Bases: KinematicsMixin, CentroidalMixin, DynamicsMixin, SnapshotMixin

    Central Pinocchio model interface for the MAX humanoid robot.

    The robot is modeled as a floating-base system.

    Responsibilities: - load the robot URDF - build the Pinocchio model - create and own the Pinocchio Data object - store the current robot state (q, v, a) - provide joint/frame information - provide the common model interface used by other modules

    inverse_kinematics(frame_name, target, q0=None, task='position', active_joints=None, freeze_floating_base=True, max_iterations=500, position_tolerance=0.0001, orientation_tolerance=0.001, step_size=0.2, damping=1e-06, enforce_joint_limits=True) ¶

    Parameters¶

    target

    If task='pose': 4x4 pose or pin.SE3.

    {'position', 'pose'}

    Position-only or full SE(3) inverse kinematics.

    bool

    float

    Position convergence tolerance in meters.

    float

    humanoid_pinocchio.dynamics ¶

    DynamicsMixin ¶

    Rigid-body dynamics computations for the robot.

    All computations use the current state stored in RobotModel.

    Conventions¶

    Mass matrix: Shape (nv, nv)

    Generalized forces

    Shape (nv,)

    Dynamic equation

    tau = M(q) @ a + nle(q, v)

    where

    nle(q, v) = Coriolis/centrifugal effects + gravity

    coriolis_forces() ¶

    Return Coriolis and centrifugal generalized forces.

    c(q, v) = C(q, v) @ v

    Returns¶

    numpy.ndarray Generalized Coriolis/centrifugal force vector with shape (nv,).

    coriolis_matrix() ¶

    Return the Coriolis matrix C(q, v).

    The rigid-body dynamics equation is:

    tau = M(q) @ a + C(q, v) @ v + g(q)
    Notes¶

    Pinocchio's computeCoriolisMatrix() modifies several fields of its Data object. Therefore, a dedicated Data object is used here so that computing C(q, v) does not corrupt cached kinematic or centroidal quantities stored in self.data.

    Returns¶

    numpy.ndarray Coriolis matrix with shape (nv, nv).

    forward_dynamics(tau) ¶

    gravity() ¶

    EKF ¶

    Bases: KF

    Discrete-time Extended Kalman Filter.

    The filter follows the nonlinear model

    x_k = f(x_{k-1}, ...)
z_k = h(x_k, ...)

    with covariance propagation based on the Jacobians F, L, H, and M.

    __init__(x0, P0, f, F, Q, L=None) ¶

    Initialize the Extended Kalman Filter.

    Parameters:

    Name Type Description Default
    x0 Any

    Initial state estimate.

    		 required
    P0 Any

    Initial estimation-error covariance.

    		 required
    f Callable[..., Any]

    Discrete nonlinear process model.

    		 required
    F Model

    State Jacobian of the process model.

    		 required
    Q Any

    Process-noise covariance.

    		 required
    L Optional[Model]

    Process-noise Jacobian/gain matrix. If None, additive process noise is assumed and L = I.

    		 None

    predict(*args, **kwargs) ¶

    Perform the EKF prediction step.

    Computes

    x^- = f(x^+, ...)
P^- = F P^+ F^T + L Q L^T

    Additional positional and keyword arguments are forwarded to the process model and its Jacobians.

    update(z, h, H, R, M=None, residual=None, *args, **kwargs) ¶

    Perform the EKF measurement-update step.

    Computes

    innovation = z - h(x^-)
S = H P^- H^T + M R M^T
K = P^- H^T S^-1
x^+ = x^- + K innovation

    The covariance is updated using the Joseph stabilized form.

    Parameters:

    Name Type Description Default
    z Any

    Measurement vector.

    		 required
    h Callable[..., Any]

    Nonlinear measurement model.

    		 required
    H Model

    Measurement-model state Jacobian.

    		 required
    R Any

    Measurement-noise covariance.

    		 required
    M Optional[Model]

    Measurement-noise Jacobian/gain matrix. If None, additive measurement noise is assumed and M = I.

    		 None
    residual Optional[Callable[..., Any]]

    Optional custom residual function. This is useful for quantities such as wrapped angles.

    		 None

    Additional positional and keyword arguments are forwarded to h, H, and M.

    LKF ¶

    Bases: KF

    Discrete-time Linear Kalman Filter.

    The filter follows the linear model

    x_k = F x_{k-1} + G u_{k-1} + w_{k-1}
z_k = H x_k + v_k

    with

    w ~ (0, Q)
v ~ (0, R)

    __init__(x0, P0, F, Q, G=None) ¶

    Initialize the Linear Kalman Filter.

    Parameters:

    Name Type Description Default
    x0 Any

    Initial state estimate.

    		 required
    P0 Any

    Initial estimation-error covariance.

    		 required
    F Model

    State-transition matrix.

    		 required
    Q Any

    Process-noise covariance.

    		 required
    G Optional[Model]

    Optional control-input matrix.

    		 None

    predict(u=None, *args, **kwargs) ¶

    Perform the LKF prediction step.

    Computes

    x^- = F x^+ + G u
P^- = F P^+ F^T + Q

    If no control input is used:

    x^- = F x^+

    update(z, H, R, *args, **kwargs) ¶

    Perform the LKF measurement-update step.

    Computes

    innovation = z - H x^-
S = H P^- H^T + R
K = P^- H^T S^-1
x^+ = x^- + K innovation

    The covariance is updated using the Joseph form.

    SRCKF ¶

    Bases: KF

    Discrete-time Square-root Cubature Kalman Filter.

    This implementation follows the SRCKF formulation used in the supplied MATLAB Q3 exercise.

    The filter uses 2n cubature points

    zeta = sqrt(n) * [I, -I]

    and stores a lower-triangular square-root covariance factor

    P = sqrt_P @ sqrt_P.T

    Process and measurement noises are assumed additive.

    SRUKF ¶

    Bases: UKF

    Square-root UKF following the MATLAB Q3 SRUKF-style algorithm.

    The filter stores a lower-triangular square-root covariance factor sqrt_P such that

    P = sqrt_P @ sqrt_P.T

    For consistency with the supplied MATLAB implementation, covariance matrices are reconstructed during prediction and update and are then re-factorized using a numerically safe Cholesky decomposition.

    dcm_to_quaternion(T) ¶

    Convert a 3x3 DCM to a scalar-first quaternion.

    Parameters¶

    T : array-like, shape (3, 3) Direction cosine / transformation matrix using the same convention as quaternion_to_dcm().

    Returns¶

    numpy.ndarray, shape (4,) Unit quaternion in scalar-first form:

        [q0, q1, q2, q3]
    Notes¶

    In this convention:

    T = R.T

    where R is the rotation matrix used by quaternion_to_rotation_matrix().
